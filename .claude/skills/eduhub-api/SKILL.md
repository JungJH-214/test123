# EduHub 백엔드 API 추가 절차

기준 예시는 `course` 패키지다. 조회는 `CourseQueryService`·`CourseController`, 쓰기는 `CourseCommandService`·`CourseAdminController`를 본다. 요구사항은 `docs/requirements.md`(FR, NFR, D-xx)를 따르고, 애매한 규칙은 지어내지 말고 사용자에게 묻는다.

**환경 제약:** Java 11 + Spring Boot 2.7이다. `javax.*`를 쓰고, `record`와 `ProblemDetail`은 쓸 수 없다.

## 1. Flyway
- **스키마 변경:** `ddl-auto: validate`라서, 테이블이나 컬럼이 바뀌면 반드시 `src/main/resources/db/migration/V{다음 번호}__{설명}.sql`을 추가한다. 이미 적용된 V 파일은 고치지 않는다.
- **SQL 문법:** H2(test 프로필)와 PostgreSQL 양쪽에서 돌아가게 쓴다. ID는 `BIGINT GENERATED BY DEFAULT AS IDENTITY`, 문자열은 `VARCHAR(n)`(`TEXT`는 쓰지 않음), FK 컬럼에는 인덱스를 둔다.

## 2. 엔티티 (`{도메인}/domain`)
- **어노테이션:** `@Getter`와 `@NoArgsConstructor(access = PROTECTED)`만 붙인다. **`@Setter`는 쓰지 않는다.**
- **생성:** private 생성자와 `create(...)` 정적 팩토리로 만들고, 초기 상태는 팩토리에서 정한다.
- **상태 변경:** `update(...)`, `close()`, `isClosed()` 같은 의미 있는 메서드로만 바꾼다.
- **연관관계:** `@ManyToOne(fetch = LAZY, optional = false)` 단방향을 기본으로 한다. 컬렉션 양방향은 N+1 위험(NFR-02)이 있어 필요할 때만 둔다.
- **enum:** `@Enumerated(EnumType.STRING)`으로 저장한다.

## 3. DTO (`{도메인}/dto`)
- **응답:** `final` 클래스에 private 생성자, `from(엔티티)`나 `of(...)` 정적 팩토리, getter를 둔다. 엔티티를 그대로 반환하지 않는다.
- **요청:** `final` 클래스에 `@Getter`, `@NoArgsConstructor(access = PRIVATE)`, `@AllArgsConstructor`를 붙인다. 검증은 Bean Validation(`@NotBlank`, `@NotNull`, `@Size`, `@Min`)으로 하고, `message`는 한국어로 쓴다(예: "필수 입력입니다"). 숫자는 `@NotNull`이 동작하도록 `Integer`로 둔다.
- **페이지 응답:** `common/dto/PageResponse.from(page)`를 쓴다(page는 0부터).

## 4. Repository (`{도메인}/repository`)
- **기본:** `JpaRepository<엔티티, Long>`를 상속한다. 동적 검색이 필요하면 `JpaSpecificationExecutor`와 `XxxSpecifications`(값이 비면 `null`을 반환)를 쓴다.
- **소속 확인:** 하위 리소스는 `findByIdAndParentId`처럼 상위 리소스에 속하는지까지 확인하는 메서드로 찾는다.

## 5. Service (`{도메인}/service`)
- **클래스 분리:** 조회는 `XxxQueryService`에 `@Transactional(readOnly = true)`, 쓰기는 `XxxCommandService`에 `@Transactional`을 클래스 단위로 붙인다.
- **DTO 변환:** OSIV가 꺼져 있으므로(`open-in-view: false`) LAZY 로딩과 DTO 변환은 서비스 안에서 끝내고 DTO를 반환한다.
- **변경 저장:** 엔티티의 상태 변경 메서드를 부르고 dirty checking에 맡긴다. 새 엔티티만 `save`한다.
- **예외:** 업무 규칙을 위반하면 도메인 예외를 던진다(`{도메인}/exception`).
  - 없는 리소스: `NotFoundException`을 상속한 `XxxNotFoundException`(code 예: `COURSE_NOT_FOUND`) → 404
  - 현재 상태에서 불가: `ConflictException`을 상속한 `XxxClosedException` 등(code 예: `COURSE_CLOSED`) → 409
- **규칙 기록:** 서비스 Javadoc에 업무 규칙을 한 단락으로 적는다.

## 6. Controller (`{도메인}/controller`)
- **경로:** 조회는 `/api/v1/{리소스}`, 관리자 쓰기는 `/api/v1/admin/{리소스}`. 상태 전이는 `POST /{id}/close`처럼 동사 하위 경로로 둔다.
- **계층:** Controller는 Service만 부른다. **Repository를 직접 호출하지 않는다.**
- **입력:** 요청 본문은 `@Valid @RequestBody`로 받는다. 등록은 `@ResponseStatus(HttpStatus.CREATED)`, 페이지 파라미터는 `@ParameterObject @PageableDefault(...) Pageable`로 받는다.
- **OpenAPI:** 클래스에 `@Tag`, 메서드에 `@Operation(summary)`를 붙인다. 응답마다 `@ApiResponse`를 달고, 에러 응답에는 `content = @Content(schema = @Schema(implementation = ErrorResponse.class))`와 에러 code를 적는다.
- **예외와 HTTP 상태:** 변환은 `common/error/GlobalExceptionHandler`가 한다.
  - `NotFoundException` → 404
  - `ConflictException` → 409
  - `@Valid` 실패 → 400 `VALIDATION_FAILED`
  - 본문 형식 오류 → 400 `INVALID_REQUEST`
  - 새 상태 코드가 필요할 때만 핸들러를 추가한다.

## 7. 테스트 (`src/test/java/...`, 메서드 이름은 `동작_결과()`)
- **Service:** `@ExtendWith(MockitoExtension.class)`에 `@Mock` Repository와 `@InjectMocks` Service를 쓴다. 정상 경로와 규칙 위반(404, 409 예외)을 모두 검증한다(NFR-05 커버리지 70%).
- **Controller:** `@WebMvcTest(XxxController.class)`에 `@MockBean` Service를 쓴다. 상태 코드, `jsonPath`, 에러 `code`(400, 404, 409)와 파라미터 전달(`ArgumentCaptor`)을 확인한다.
- **Repository:** 쿼리를 추가했으면 `@DataJpaTest`, `@AutoConfigureTestDatabase(replace = NONE)`, `@ActiveProfiles("pgtest")`로 검증한다. 로컬 PostgreSQL의 `eduhub_test`를 쓰고, `em.flush()`와 `em.clear()` 뒤에 조회한다.

## 8. 프론트 API 클라이언트 재생성
- **재생성:** 백엔드를 8080에 띄운 상태에서 `cd frontend && npm run generate:api`를 실행한다. `packages/api-client/src/generated`는 손으로 고치지 않는다.
- **새 API 클래스:** 새 `@Tag`가 생기면 `XxxApi` 클래스가 생성된다. 그 인스턴스는 `apps/course-mfe/src/api/` 한 곳에서만 만든다.
- **프론트 확인:** `npm test -w apps/course-mfe`와 `npm run typecheck -w apps/course-mfe`로 깨진 곳이 없는지 본다.

## 검증 (끝내기 전에 반드시)
```bash
cd backend && ./gradlew spotlessApply test
```
- **통과 기준:** 포맷을 적용한 뒤 테스트가 전부 통과해야 한다. 실패하면 원인을 고치고 다시 돌린다. 테스트를 건너뛰거나 지우지 않는다.
- **JDK:** `JAVA_HOME`은 JDK 11이어야 한다(`.claude/settings.local.json`의 `env`).
- **커밋:** Conventional Commits 형식으로 한다(예: `feat(course): ...`). 푸시와 PR은 사용자에게 묻는다.
